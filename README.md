# DeepAI (staged independent source copy)

Run from this directory with `python app.py`. Use `python app.py --smoke` to create and close the UI without starting file indexing or Ollama checks. Python 3.12 is the inspected runtime.

Create a fresh environment and install `requirements.txt`; do not use the original workspace `.venv`. `.env` is optional and must be created locally from your own settings. Ollama and optional Vosk model data remain external user-managed dependencies. The app stores any new local databases under this staged project root; no original database was copied. Automatic file indexing is disabled by default; set `DEEPAI_AUTO_INDEX_FILES=true` to opt into startup scanning.

The DeepX button launches the sibling `..\DeepX\deepx_main.py` as a separate process. DeepAI has no in-process Blender agent or DeepX package.

## Architecture

- `app.py` owns the CustomTkinter desktop UI, local SQLite-backed notes, reminders, conversation history and personal memory, plus file, voice, vision, chess and system utility workflows.
- `agents/` contains the HeadAgent router and specialist agents for code, files, system controls, memory, vision, research, chess, planning and review.
- `core/` provides task/context resolution, agent lifecycle and messaging, tool registration, and a facade over the app's existing memory objects.
- `ai/ollama.py` wraps Ollama's local HTTP API. Model names are configured in `config.py` or overridden with `DEEPAI_CHAT_MODEL`, `DEEPAI_TEXT_MODEL`, `DEEPAI_CODE_MODEL`, and `DEEPAI_VISION_MODEL`.
- `tools/` contains reusable file, code, web, vision, system and chess helpers.

## Chat and memory flow

The UI submits requests on worker threads. The dispatcher records user/assistant turns and calls `HeadAgent`; the HeadAgent routes actionable requests to specialist agents and sends conversational requests through Ollama's multi-turn chat endpoint. Recent conversation turns and relevant long-term memory are included as context. Explicit personal statements matching `My name is ...` or `My X is Y` can be recalled later; other text is not automatically saved as a personal fact. Model/API failures are logged and returned as user-readable status text.

## Setup and testing

Use Python 3.12 on Windows. Create a project-local virtual environment and install `requirements.txt`; install `requirements-optional.txt` only for optional features. Start Ollama separately and pull the configured models. Run the UI with `python app.py`, or use `python app.py --smoke` for a short startup check. Run the offline regression suite with `python -m pytest -q` (the tests mock chat model responses and do not require Ollama). Use a reachable local Ollama endpoint for live integration tests.

## Known limitations

Voice recognition depends on microphone/audio support and optional Vosk model files. Camera, speech synthesis, desktop controls and chess engine behavior depend on local Windows hardware and installed components. Live Ollama generation requires the Ollama service and configured models to be available. The smoke option verifies startup and shutdown, not every interactive UI action.

When explicitly enabled with `DEEPAI_AUTO_INDEX_FILES=true` or started with `rebuild index`, the file indexer scans the current user's Desktop, Documents, Downloads and Pictures. It stores file paths and metadata in the configured index database; it does not extract file contents in the current indexing pass. Review this behavior and the configured database location before enabling indexing on a machine with private files.

The file index schema stores path, filename, extension, byte size, modified time, an optional file hash, an optional content preview and an indexed flag. Current indexing populates only path/name/extension/size/modified time/indexed flag; it does not read file contents or calculate hashes. Scans omit dot-prefixed files/folders, `node_modules`, `__pycache__`, `.git`, Windows Hidden/System entries, and common credential/key names and key-store extensions. These filename rules are a safeguard, not a guarantee that every sensitive filename will be recognized. SQLite databases are plaintext and inherit the DeepAI folder's Windows ACL; protect the folder and database accordingly. Use `pause indexing`, `resume indexing`, `disable indexing`, `enable indexing`, `clear index`, or `rebuild index` in chat to manage the index. Clearing removes index rows while preserving the database file.

## GUI regression repair (2026-11-17)

- Root cause of the dead `+` control: its menu was opened by the CustomTkinter button's internal canvas click, then the global outside-click handler treated that internal canvas as outside the plus button and immediately destroyed the menu. ## Enter-key and chess responsiveness follow-up (2026-11-18)

- The Enter regression was traced to the submit/reset sequence: after sending, `send()` triggered the composer’s focus-out placeholder logic while the text widget still had focus. That inserted `Message DeepAI...` into the editor and marked it as placeholder text, so the next Enter submission was discarded as empty. The send path now clears the editor without inserting a placeholder, keeps focus ready for the next message, and binds Return/keypad Enter directly to the underlying Tk text widget. Shift+Enter continues to insert a newline.
- Chess GUI moves previously reached `make_move()` from the square-click handler synchronously; that path can include a Stockfish search for the opponent reply. GUI move and analysis operations now run on one serialized worker at a time; results return to Tk through the UI queue, stale results are discarded after closing the board, and engine searches have bounded limits and heuristic fallback. Engine shutdown also runs off the Tk thread. This fixes the blocking code path; the original freeze was not reproduced with a live Stockfish engine in this environment.
